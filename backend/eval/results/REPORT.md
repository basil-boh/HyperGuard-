## Read this first — what these numbers are not

The dataset is **synthetic**. Transfer features are drawn from distributions written by
hand in `eval/generate.py`; utterances are LLM-generated from plain-language scam briefs.
That design choice buys one thing and costs another:

* It **buys** an escape from the circularity that made the old fixtures useless — the
  utterances are produced without ever seeing the classifier's indicator lists, and the
  dataset-integrity section below measures how well that worked.
* It **costs** external validity. These results describe how the system behaves on the
  world as `generate.py` imagines it. If those distributions are wrong about how scams
  differ from legitimate transfers, every number here is wrong in the same direction, and
  confidently so.

**What would fix that:** sourced cases from SPF scam briefs, ScamShield advisories, and
published enforcement write-ups, labelled by two annotators with inter-rater agreement
reported. That is the upgrade that turns these from internal-consistency checks into
evidence. Until then, do not put these numbers on a slide without the word "synthetic"
next to them.

### Three specific things you must not over-read

**1. The LLM classifier's perfect score is contaminated.** The same model that generated
the utterances also classifies them in Option B. It is grading its own handwriting, and a
1.000 macro-F1 is the signature of that, not of a solved problem. The keyword matcher has no
such advantage, so the *comparison* still means something — but treat the LLM's absolute
numbers as an upper bound that will not survive contact with real transcripts. **Fix:**
regenerate with a different model family than the one under test.

**2. Option C's E3 models the graph path where the Educator runs.** That is the path you get
*without* telephony credentials. On the live telephony path the graph skips the Educator
entirely (`graph.py:97-101`), verification is never set to `verified`, and the system
therefore behaves like **E2**, not E3. So the E2→E3 gap is best read as *the value of fixing
the live path*, not as a description of what the deployment does today.

**3. A false-positive rate this high is the headline, not a footnote.** See Option A's
per-slice table before quoting any catch rate.


**Dataset:** 320 cases — `legit_obvious` 65, `legit_suspicious` 121, `scam_adversarial` 38, `scam_clean` 96. Utterances: llm. LLM comparisons: enabled.

## Dataset integrity — how circular is this?

The old fixtures were written in the same file as the indicator lists they're matched against, so testing on them proved nothing. These numbers check the replacement actually escaped that, rather than assuming it.

Utterances generated by: **llm**

| Slice | n | Cases containing a verbatim indicator | Utterances | Similarity to shipped fixtures |
|---|---|---|---|---|
| `scam_clean` | 96 | 85.4% | 52.4% | 0.12 mean / 0.17 max |
| `scam_adversarial` | 38 | 89.5% | 50.9% | 0.08 mean / 0.11 max |

**How to read this.** Some verbatim overlap on the clean slice is *correct* — real victims of a police-impersonation scam genuinely say "safe account", and utterances with none of the natural vocabulary would be unrealistic. What matters is that the adversarial slice is much lower (that's the test working) and that fixture similarity stays low (the generator didn't rediscover the answer key). The old fixtures would score 100% on column three by construction.
